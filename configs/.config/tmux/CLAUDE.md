# Project: tmux config

## Overview
- **Type**: tmux configuration (part of ~/.dotfiles, symlinked to ~/.config/tmux)
- **Stack**: tmux 3.7c, tpm plugins, kitty terminal, niri compositor
- **Package Manager**: bun
- **Started**: 2026-09-29 (this file)

## Architecture Decisions
- File layout: `tmux.conf` (options, keys, plugins) → `theme.conf` (catppuccin options, sourced BEFORE tpm because the plugin only sets unset options) → tpm `run` → `status.conf` (status bar, sourced AFTER tpm so it overrides catppuccin and can use `@thm_*`). Custom status modules live one per file in `modules/`; shell helpers in `scripts/`.
- Status bar: left = COPY / SYNC badges (zoom is shown inside the window tab, never as a separate badge: peach zoom icon + pane count in `@window_label`; the catppuccin zoom flag is dropped from `@catppuccin_window_flags_icon_format` to avoid a duplicate icon); right = Alt+a hint pill for Claude panes waiting/done (hidden when none), git branch (hidden outside repos), session +N other sessions. Window tabs use catppuccin icon flags (bell, activity, silence, mark only). The current-window and last-window flag icons were removed from `@catppuccin_window_flags_icon_format` at user request (the tab colour already shows the active tab); don't re-add them. No clock/battery/CPU: the niri DMS bar shows those.
- The Alt+Tab target is not displayed anywhere (user removed it from both the bottom bar and a top pane-border line). `@previous_session_name` is still published by `scripts/session-history` but unused. Don't re-add it.
- Tabs: `@window_label` (status.conf) = program icon (`scripts/window-icon`, falls back to the program name) + folder basename (Claude windows: Claude's task title instead, see below), or `#W` when the window was renamed by hand (`rename-window` turns `automatic-rename` off for that window; `set -wu automatic-rename` goes back to the folder) + pane count when split + `@claude_marker`. Used by catppuccin window text and the Alt+s session list (`choose-tree -F`).
- Claude Code state per PANE (several Claude sessions can share a window/session): `~/.claude/hooks/tmux-claude-state.sh` sets pane option `@claude_state` (UserPromptSubmit/PostToolUse → working, Notification → waiting, Stop → done unless the window is visible, SessionEnd → clear). Tabs (`@claude_marker`) show a count per state (state icon, plus the number when >1); the Alt+s picker shows coloured Claude icons instead. Counts come from `#{n:#{P:…}}` formats (`@claude_*_count`). `pane-focus-in[10]` (fires on window switch, session switch and terminal refocus) runs `scripts/claude-clear-done` to acknowledge done panes in the visited window and close their desktop notifications. monitor-activity stays off on a window until its last Claude pane ends. The hook also keeps pane options `@claude_state_since` (epoch when the state last changed), `@claude_task` (last prompt, from the UserPromptSubmit payload) and `@claude_prompt_started_at`, and runs `refresh-client -S` on every client when the state changes.
- Claude tab names: Claude Code sets the pane title to a generated task name after the first prompt (`✳ Fix login redirect`; a hook can't do this: `sessionTitle` only works in SessionStart). `@claude_title_full` strips the leading glyph; `@claude_tab_title` cuts it at a word boundary to max 20 chars with no ellipsis (user's choice; titles over 20 keep their first 21 chars minus the trailing partial word, a single long word is hard-cut); `@claude_has_title` = active pane runs claude and the title isn't the default `Claude Code`. Then the tab shows the title instead of the folder, in the normal tab colour. The Alt+o dashboard shows the title before the last prompt. tmux session names stay project paths (tmux-leap matches projects by them).
- Rename a Claude tab: prefix N = `scripts/claude-rename-tab` (run-shell -b). Suggests a name from the pane's last 6 prompts (transcript path in pane option `@claude_transcript`, kept by the state hook; falls back to `@claude_task`) via `claude -p --model haiku --no-session-persistence --strict-mcp-config --settings '{"disableAllHooks":true}'` (~5 s; hooks off so it can't fire state/notification hooks), then `command-prompt -b -I <suggestion>`: Enter keeps it, edit it, empty = back to Claude's own title. Stored as pane option `@claude_title_override` (template uses `"%%%"`, which escapes quotes); `@claude_title_full` prefers it, so tab, Alt+o and the Alt+a pill all follow. Cleared when the Claude session ends. Prefix N was free (tmux default has no N).
- Claude navigation: `Alt+a` = `scripts/claude-next` (waiting panes oldest first, then done ones; pressing again moves to the next, wraps; working/idle skipped). `Alt+o` = `scripts/claude-dashboard` (fzf popup of every Claude pane, sorted waiting → working → done → idle, state + age + project + window + last prompt, preview = pane screen at the bottom, enter jumps, ctrl-r refresh, Alt+o again closes it via fzf `alt-o:abort` because keys inside a popup reach fzf, not tmux; binding stores `@picker_origin_client`). Both jump through `scripts/claude-focus-pane PANE [CLIENT] [--raise-terminal]`; `--raise-terminal` also focuses the kitty window via `scripts/niri-window-of-client` (walks up from the client pid to a niri window pid).
- Alt+a hint `@claude_attention_badge` (status-right, before git): one pill `󶀀 N waiting · N done  <name>`, where <name> is the pane Alt+a jumps to next (`claude-next --peek '#{pane_id}'` via `#()`, refreshed every status-interval; same name as its tab and Alt+o row: task title cut to 20 chars, else the project; user asked for the name instead of the literal "Alt+a"), counting exactly what Alt+a visits (waiting/done Claude panes in every session except the window you're in). Red while any is waiting, green when only done ones are left, hidden when none. Replaced the earlier per-state pills for other sessions only (2026-10-02: user didn't notice them and wanted the Alt+a hint). Pure formats: `#{S:#{W:…}}` loop skipping the client's active window; count = length of the 1/0 string from `#{==:…}` with zeros stripped.
- Desktop notifications: `~/.claude/hooks/claude-notify.sh done|waiting` (Stop, and Notification with matcher `permission_prompt|elicitation_dialog`; replaced `notify-stop.sh` 2026-10-02). Title names the project and, for done, how long the prompt took; waiting is urgency critical with Claude's message. Skipped when the pane is active in an attached session whose kitty window is focused in niri. One notification per pane (`@claude_notification_id`; the previous one is closed first, `gdbus … CloseNotification`); closed when the pane goes back to working, ends, or its window is visited. The `default` action (click) runs `claude-focus-pane --raise-terminal`; the script re-runs itself detached (`setsid -f … --deliver`) so the hook returns at once while `notify-send --wait` waits for the click. Daemon is quickshell (DMS), which supports actions.
- Alt+s = `scripts/session-picker` (fzf in a rounded popup): most recent first, current last as "(here)", Claude marker, window icons, live preview; one icon per distinct pane program with a count when >1 (never three copies); Claude panes use the Claude icon itself as the state marker, coloured red waiting / yellow working / green done / dim idle, each with its own count, Enter switch, ctrl-x kill (y/N), unknown name + Enter creates. The binding stores `#{session_id}` in `@picker_origin_session` first.
- Colours: always `#{@thm_*}` tokens from catppuccin, never hex, in status formats.
- `Alt+Shift+w` = new window in the current folder with `claude --dangerously-skip-permissions` typed into it (send-keys, so the interactive shell PATH applies and the shell stays when Claude exits). Pairs with `Alt+w` (plain new window). Prefix C stays tmux's customize-mode.
- `status-right` must keep `#(…/tmux-continuum/scripts/continuum_save.sh)` or continuum autosave stops.
- Prefix is `Alt+Space` (`M-Space`).
- Two-layer keymap direction: `Alt+key` (root table, no prefix) for frequent actions; prefix + mnemonic key for the rest.
- `Alt+Tab` = `scripts/session-history previous`: an MRU queue of session ids in the global option `@session_history`, pushed by `pane-focus-in[20]`, pruned by `session-closed[20]`. Alt+Tab jumps to the newest surviving session that isn't the current one, so killing a session falls through to the next one. The status bar target is `@previous_session_name` (not `client_last_session`, which goes stale when that session dies). niri's `Alt+Tab` / `Alt+Shift+Tab` were removed from `~/.config/niri/config.kdl` `recent-windows { binds {} }` so the key reaches tmux.

## Preferences & Rules
- Harpoon is not used; don't reintroduce it or plan around it.
- Keep tmux defaults for prefix splits (`"` below, `%` right) and copy mode (`[`). Don't propose `|`/`-` or `v` replacements.
- Alt+Tab means "go back to the previous session", not cycle through sessions. No Alt+Shift+Tab binding.
- Status bar keeps its background (`@catppuccin_status_background "#{@thm_bg}"`); user tried transparent and asked for the bg back. Popups (tmux-leap etc.) ARE transparent (`popup-style default`).
- Window tabs are left-aligned (`status-justify left`). User hates centred tabs.
- Tab separators and badges put `bg=#{@thm_bg}` behind round glyphs (not `default`), so corners match the bar.
- Killing a session switches to the most recently used session instead of detaching (`detach-on-destroy off`).
- Before adding any `bind -n M-<key>`, check the Alt-key owners below.
- No per-window accent colours on Claude tabs or dashboard rows (tried 2026-10-02, user found them distracting). Task names stay, in the normal colour.
- Alt+f picker lines: path first, no separate name column, icons directly after the path (not padded to a far column). List/preview split 50/50.

## Patterns & Conventions
- Splits and new windows always use `-c "#{pane_current_path}"`.
- Destructive bindings go through `confirm-before`, except closing a pane: Alt+x / prefix x close instantly when the pane is an idle shell and ask only when a program or background job is running (non-shell `pane_current_command`, or the shell has children via `pgrep -P #{pane_pid}`).
- Add `-N "note"` to bindings so `prefix ?` lists readable names.

## Learnings & Corrections
- ❌ Deleting the whole niri `recent-windows { binds { … } }` block → ✅ Keep the block. Leaving it out restores niri's default Alt+Tab and Mod+Tab. Remove individual lines only.
- ❌ Assuming a cycling session switch (`switch-client -n/-p`) → ✅ User wanted previous-session toggle (`switch-client -l`).

- ❌ Running yazi in `display-popup` → quit hangs exactly 5 s (yazi ≥26.9.1 waits for a terminal probe; tmux popups/hidden panes never deliver passthrough replies, upstream issue sxyazi/yazi#4361 closed not-planned). Env vars can't hide tmux (detected via XTVERSION reply). ✅ Open yazi in a visible pane (`split-window -h -Z`): quit is ~6 ms and image previews work.

- ❌ Two `%hidden MODULE_NAME=…` + `source` pairs in one file → only the last module is created (%hidden is resolved when the file is parsed, before commands run). ✅ One module per file under `modules/`.
- ❌ Verifying `#()` job output with `tmux display -p` → always empty (display doesn't wait for jobs). ✅ Attach a pty client to a `-L` test server and read the drawn status line.
- ❌ catppuccin `rounded` window style with a transparent bar → tab corners render as opaque dark squares in kitty (the style draws separators with `reverse`, and kitty only makes default-bg cells transparent). ✅ `custom` window style with `#[fg=<pill colour>,bg=default]` round glyphs in `theme.conf`.
- ❌ Switching themes and only reloading → old theme's `status-bg` / `window-status-style` stay set in the live server, so the bar stays opaque. ✅ `status.conf` explicitly sets `status-style` from `@thm_bg` and resets `window-status-style` / `window-status-current-style` / `popup-style`. `status-bg` overrides `status-style` when not `default`, so never set it.
- ❌ tmux activity alerts on Claude Code windows → always on (its TUI redraws constantly). ✅ Hook script sets `monitor-activity off` per Claude window (SessionStart and every state, unset on SessionEnd), and the tab's new-output icon (`@catppuccin_window_flags_icon_format` in theme.conf) also requires `monitor-activity` on and `pane_current_command != claude`. tmux still sets `window_activity_flag` with monitoring off, so the format check is required.
- ❌ Mapping every Claude `Notification` to waiting → the `idle_prompt` nudge (~60 s after Stop) overwrote done with the question mark. ✅ Notification hook has matcher `permission_prompt|elicitation_dialog`, and the script also ignores other `notification_type`s.
- ❌ Reading `tmux list-sessions` with `IFS=$'\t'` → empty fields (never-attached sessions) collapse and columns shift. ✅ Use `\x1f` as the separator.
- ❌ Detecting the current session inside a popup with `tmux display` or `$TMUX_PANE` → wrong session; popup commands and `-e` aren't format-expanded. ✅ Binding runs `set -gF @picker_origin_session "#{session_id}"` before `display-popup`.

- ❌ `switch-client -l` / `#{client_last_session}` for Alt+Tab → single pointer, dead after that session is killed. ✅ MRU queue in `scripts/session-history`.

- ❌ Storing `@claude_state` as a window option → two Claude panes in one window overwrite each other, and pane-level reads fall through to a stale window value. ✅ Pane option, and unset any leftover window-level `@claude_state` after migrating.

- ❌ Our own hooks on `client-session-changed` / `session-window-changed` → ueberzugpp (yazi's image fallback) runs `set-hook -g client-session-changed …` without an index, which replaces the whole array, and `-gu` on exit; it also sets `session-window-changed` per session, which shadows the global one. Alt+a into another session then never cleared done, and Alt+Tab history stopped recording. ✅ Hang our handlers on `pane-focus-in[N]` (ueberzugpp doesn't touch it; `focus-events on` comes from tmux-sensible). Check `tmux show-hooks -g` when a hook-driven feature stops working.

- ❌ `[[ cond ]] && cmd` as the last line of a hook script → exits 1 when cond is false and tmux shows "returned 1" in a message. ✅ Use `if … then … fi` (or end with `exit 0`) in scripts run by `run-shell`.

- Claude icon: Nerd Fonts has no Claude logo, so `scripts/build-claude-glyph` generates a one-glyph font (`U+F6000`) from the real logo outline in `assets/claude-logo.svg` (simple-icons, CC0) into `~/.dotfiles/fonts/.local/share/fonts/claude-glyph/` and links it into `~/.local/share/fonts`. `scripts/window-icon` prints it for `claude`. Rerun the script on a new machine. Kitty must map it explicitly: `symbol_map U+F6000 Claude Glyph` in `~/.config/kitty/kitty.conf` (fontconfig fallback alone rendered a box). Reload kitty with ctrl+shift+f5, or restart it, after changing fonts.

- ❌ Nerd Font icons followed by a digit or at line end (`⋇2`) → kitty squeezes them into one cell, so they look tiny. ✅ kitty draws private-use glyphs two cells wide only when a space or en space follows; `pane_icons` puts an en space (U+2002) after every icon.

- ❌ Icon at the end of an fzf line → full size for a few seconds, then small. fzf trims trailing whitespace (incl. the en space) and pads with spaces; tmux's later popup redraw turns that padding into erased cells, which kitty doesn't count as a space. ✅ `session-picker --annotations` ends each line with a blank braille cell (U+2800, not whitespace), so the en space survives. Check rendering with `tools/capture-popup` (screenshot after ~10 s), not `capture-pane`.

- ❌ Copying status.conf snippets from tool output → the Powerline/half-circle glyphs (U+E0B6/U+E0B4) are invisible there and get lost. ✅ Write them as `\ue0b6` / `\ue0b4` escapes and check with `od -c`.

- ❌ `{m,n}` regex quantifiers inside `#{s/…/…/:…}` → the braces end the format early and garbage is printed. ✅ Avoid braces: cut with `#{=N:…}` and trim with brace-free regexes.

- ❌ `#{?…,x,}` inside another conditional's branch (e.g. `#{?skip,,#{P:#{?#{==:…},x,}}}`) → expands to nothing. ✅ Use `#{==:…}` (gives 1/0) and count with `#{n:#{s/0//:…}}`. Test formats with `tmux display -p -c <client>`.

- ❌ `tmux command-prompt` from a script without `-b` → the script blocks until the prompt is answered. ✅ Use `-b`. Test prompts on a throwaway server with a hidden client: `script -qfc 'tmux -L x attach' /dev/null < fifo` and write keys into the fifo.

- ❌ fzf `reload` with the list piped in by `tail -f` on stdin → reload never runs (fzf waits for stdin to end). ✅ Stream the growing list through `--bind 'start:reload(tail -f …)'` with stdin closed, so fzf can stop it.

- ❌ `--no-sort` in the shared `fzf-style.sh` → Alt+f kept list order while filtering, so typing `stt` didn't put stt first. ✅ `--no-sort` only in session-picker (MRU order matters there); project-picker uses `--scheme=path --tiebreak=begin,length`.
